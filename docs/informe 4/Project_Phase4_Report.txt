1     Introducción
El proyecto estima el número de edificaciones y el área de techos aptos para paneles solares
en los 170 municipios con Programas de Desarrollo con Enfoque Territorial (PDET), con
MongoDB y dos conjuntos abiertos de huellas de edificios: Microsoft Global ML Building
Footprints y Google Open Buildings v3. Esta entrega final calcula las métricas por municipio
y fuente, evalúa su sensibilidad al criterio de techo apto, compara las dos fuentes, presenta
los resultados en mapas y discute sus alcances y lı́mites. El Cuadro 1 resume el recorrido y
el Cuadro 2 relaciona esta entrega con las secciones y los archivos del repositorio (https:
//github.com/SamT81/Proyecto-ABD).

2     Datos y Método en Breve
Los lı́mites provienen de la capa municipal del Marco Geoestadı́stico Nacional 2025 del
DANE, filtrada a los 170 municipios PDET. De Microsoft se descargaron 125 quadkeys
(373.4 MB) y de Google 8 celdas S2 (3.1 GB), solo las particiones que intersectan los munici-
pios PDET: de 4 595 615 y 31 499 115 registros leı́dos, el ETL conservó 1 761 043 y 2 694 782
dentro de PDET. Cada edificio se asignó a un solo municipio con su punto representativo,
se reparó si era inválido (28 en Microsoft) y se midió en EPSG:9377. La carga a MongoDB
tomó 82 s y 39 s con 4 procesos, con los ı́ndices creados después, y los conteos coinciden con
los del ETL. Los detalles están en los informes de las entregas 2 y 3.

3      Resultados por Municipio y Fuente
3.1     La colección results
src/03 build results.py agrega cada colección de edificios por municipality code con
una sola agregación de MongoDB y escribe el resultado con $merge en results. No hay
join espacial: el municipio se asignó en el ETL, y el ı́ndice compuesto (municipality code,
area m2) apoya la agrupación. Cada documento guarda los parámetros del criterio y la
fecha de cálculo (Cuadro 3). El ı́ndice único (municipality code, source) y $merge con
whenMatched: replace hacen que repetir el cálculo reemplace los documentos en lugar de
duplicarlos.

 Campo                                  Tipo          Descripción
 municipality code                      String        Código DIVIPOLA del municipio PDET.
 source                                 String        microsoft o google.
 building count                         Int           Edificios del municipio en la fuente.
 total roof area m2                     Double        Suma de area m2 de todos los edificios.
 suitable count, suitable area m2       Int, Double   Techos aptos y su área.
 params                                 Object        min area m2,      min confidence      (solo
                                                      Google) y crs area.
 computed at                            Date          Fecha y hora del cálculo.

                         Table 3: Documentos de la colección results.


1   { $group : { _id : " $municipality_code " , building_count : { $sum : 1 } ,
2                   total_roof_area_m2 : { $sum : " $area_m2 " } ,
3                   suitable_count : { $sum : { $cond : [ { $and : [ { $gte :[" $area_m2 " ,15]} ,
          { $gte :[" $confidence " ,0.70]} ] } , 1 , 0 ] } } ,
4                   suitable_area_m2 : { $sum : { $cond : [ { $and : [ { $gte :[" $area_m2
        " ,15]} , { $gte :[" $confidence " ,0.70]} ] } , " $area_m2 " , 0 ] } } } }
5   { $project : { municipality_code : " $_id " , source : " google " , params : {...} ,
        computed_at : ... } }
6   { $merge : { into : " results " , on : [" municipality_code " , " source "] , whenMatched : "
        replace " } }

7      Discusión, alcances y limitaciones
Escenario recomendado para planeación (UPME). Dado que las dos fuentes presen-
tan una correlación lineal muy alta (r = 0.9855) y coinciden en los municipios prioritarios,
pero tienen un 71.2 % de solapamiento espacial, los resultados no son aditivos. Para ejercicios
de planeación energética territorial se recomienda adoptar Microsoft (221.07 km2 ) como
lı́nea base por su cobertura completa en los 170 municipios PDET y estabilidad frente al um-
bral de tamaño, y Google (206.28 km2 con confianza ≥ 0.70) como escenario conservador,
conformando un intervalo de referencia entre 206.28 y 221.07 km2 (acotado globalmente entre
130.80 y 222.35 km2 según sensibilidad).

Limitaciones técnicas y fı́sicas.
    • Tope geométrico superior: Las huellas satelitales representan la proyección bidimen-
      sional en planta de la cubierta, no la superficie instalable efectiva. El aprovechamiento
      real requiere descontar inclinación, orientación (acimut), sombras de vegetación o edifi-
      caciones vecinas, obstáculos en cubierta (tanques, claraboyas) y capacidad estructural.

    • Vacı́os de cobertura en zonas nubosas: Google Open Buildings v3 no contiene
      registros en cinco municipios de Antioquia y Chocó, lo que subestimarı́a el potencial
      regional del Pacı́fico y Urabá si se empleara como fuente única.

    • Sensibilidad al umbral de confianza: En Google, elevar el corte de confianza de 0.60
      a 0.80 reduce el área apta en 40.5 %, especialmente en edificaciones rurales pequeñas o
      con techos de baja reflectancia.


8      Conclusiones y trabajo futuro
Se implementó un flujo geoespacial reproducible e idempotente sobre MongoDB 7 capaz
de procesar y consultar 4,455,825 edificaciones en los 170 municipios PDET de Colombia.
La separación entre almacenamiento espacial en WGS84 (EPSG:4326 con ı́ndice 2dsphere),
cálculo métrico de áreas en proyección oficial colombiana (EPSG:9377), carga paralela con
bitácora SHA-256 (ingestion log) y materialización mediante $merge permitió reducir las
consultas espaciales a milisegundos y recalcular escenarios de sensibilidad en una sola pasada
de agregación.
     Como trabajo futuro para transformar el potencial geométrico estimado (206.28–221.07 km2 )
en generación eléctrica efectiva (MWh/año), se propone integrar mapas municipales de ir-
radiación solar horizontal (UPME/IDEAM), factores de aprovechamiento efectivo derivados
de modelos digitales de elevación o LiDAR, y restricciones de capacidad de conexión en las
redes locales de distribución.
